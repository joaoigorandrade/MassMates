[2026-10-22] [Runtime configuration]: The publishable key and the project URL come from `Bundle.main.infoDictionary` (`SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, injected through `Project.swift` `infoPlist:`) -> a Swift literal would let the key drift from the dashboard and would break the "fail loudly when the configuration is missing" rule.
[2026-10-22] [401 handling]: The `apikey`/`Authorization` headers are added by `SupabaseAuthInterceptor`, but the refresh-and-retry lives in an `AuthenticatedNetworkClient` wrapper the app owns -> the `HTTPInterceptor` response hook returns `Void`, so it cannot replay a request, and the `Networking` package is a shared dependency that must not be modified.
[2026-10-22] [Concurrent refresh]: The session store is an actor that owns the refresher and serialises concurrent refreshes with a waiter list -> a `401` storm must produce exactly one `refresh_token` call, and a `Task` held in an actor would have inherited the actor's isolation.
[2026-10-22] [Keychain]: The session is persisted with Apple's `Security` framework (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`) behind the `KeychainStoring` protocol -> there is no third-party keychain wrapper in the repo, and the store must be injectable so the unit tests never touch the real Keychain.
[2026-10-22] [Service protocols]: Every community/check-in protocol method became `async throws` -> network I/O cannot be expressed by a synchronous signature, and the typed throws (`CommunityGroupError`, `CommunityGroupsError`, `CheckInValidationError`) were kept and extended with `.network`/`.notAuthorized`/`.lastAdminCannotLeave`.
[2026-10-22] [In-memory doubles]: `LocalCommunityGroupsService` / `LocalCheckInEngineService` were kept (not deleted) and are now the offline fallback of the composition root -> the existing unit tests depend on them and the app must degrade gracefully when the backend is unreachable.
[2026-10-22] [Private diary]: `CheckInSubmitting.privateDiaryEntries()` stayed synchronous -> it is a local-only read (the Spiritual Diary never leaves the device) and the diary view renders it from a computed property.
[2026-10-22] [Sacred privacy]: `SupabaseCheckInService` sends `p_reflection = null` and `p_photo_path = null` for every private check-in and for every `confession` -> the backend rejects a private check-in that carries content (`private_check_in_cannot_hold_content`), and the private text must never leave the device. Covered by `CheckInPrivacyTests`.
[2026-10-22] [Feed cursor]: The `next_cursor` returned by `public.get_feed_posts` is stored per group and passed back **unchanged** as `p_before` -> the cursor is the composite `"<ISO-8601>|<uuid>"` keyset; a bare timestamp would skip rows sharing a `created_at`.
[2026-10-22] [Realtime]: The Realtime client speaks the minimum of the Phoenix v2 protocol over the `Networking` WebSocket adapter and re-joins the topics when the socket reconnects -> `postgres_changes` is RLS-filtered server-side, and the client must never assume it sees every row.
[2026-10-22] [AdMob SSV]: `begin_ad_reward` returns the `transaction_id` that must travel to the ad network as the custom parameter `massmates_txn` -> the server-side verification only grants the reward when the token matches. The call site lives in `RewardedAdCoordinator` behind the `RewardedAdPresenting` seam because the AdMob SDK is not linked in the project yet.
[2026-10-22] [Deep links]: `CFBundleURLTypes` with the `massmates` scheme was added to `Project.swift` -> the app already handled `massmates://join/:code` deep links but had no plist entry, so the system never delivered the URL.
[2026-10-22] [Dated challenge]: `GroupCreationDraft` carries `startsOn`/`endsOn` (optional) and the create-group form shows two `DatePicker`s for the "Dated Challenge" type (default: today → today + 40 days) -> `public.create_group` rejects a challenge without `starts_on` + `ends_on`, and the product plan requires the user to pick the window.
[2026-10-22] [Challenge dates on the wire]: `p_starts_on` / `p_ends_on` are `yyyy-MM-dd` strings formatted in the **current calendar and timezone** (never UTC) -> the Postgres `date` type has no time zone, and a challenge opened at 22h in São Paulo belongs to the local day.
[2026-10-22] [Challenge length]: The window length is counted on a **UTC** calendar between the two local midnights -> a daylight-saving transition must not shorten or lengthen a challenge by a day.

[2026-10-22] [Auth callback]: `massmates://auth/callback` resolves to a new `AppRoute.authenticationCallback` whose destination exchanges the credentials for a session and dismisses back into the app -> a magic link must land the user in the app, not on a dead route.

[2026-10-22] [Invite code]: The invite code is a CAPABILITY — the server only returns it to the group admin, so the "share / invite" affordance is gated on `inviteCode != nil` and the in-memory double hides it from a plain member too.
[2026-10-22] [Feed comments]: The encouraging comments of a feed post are real group content (`public.feed_post_comments`). [2026-10-22] [Comment body]: The composer mirrors the server's limits (trimmed, 1..500 characters): a counter, a disabled send button past the limit and a quiet inline message — the 500-char rule lives in the UI, not only on the server.
