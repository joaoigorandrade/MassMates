# A7 — decisions (liturgical content & monetization)

- [2026-10-22] [Liturgical calendar]: The calendar is COMPUTED from the general Roman calendar rules (`private.easter_sunday` + `private.liturgical_calendar`) instead of a hand-written year table -> the seed is reproducible for any year and the Easter/Advent/Ash-Wednesday anchors cannot drift; a literal 730-row table would have been unverifiable and would silently rot.
- [2026-10-22] [Scripture text]: The seed writes NO Scripture text, NO psalm text and NO saint biography; `daily_readings.text` columns stay NULL and `is_complete` stays false -> the product plan demands the official CNBB text verbatim and inventing a passage would be a serious religious error; the texts arrive only through an authenticated `service_role` ingest pipeline.
- [2026-10-22] [Liturgical colour]: A solemnity or a feast of martyrs carries its own colour and every other day takes the colour of its season -> the colour is a property of the day, not of the season; writing only the season default would show green on All Saints and red on a Lenten optional memorial (liturgically wrong in the Today header).
- [2026-10-22] [Feast names]: Only the fixed-date solemnities whose date AND Portuguese liturgical name are certain are named; the Annunciation is deliberately left empty -> in 2026 and 2027 it falls in Holy Week and is transferred to the Monday after the Second Sunday of Easter, a rule that must come from the authoritative calendar; accuracy beats completeness.
- [2026-10-22] [Reward ledger]: `public.grant_reward` is a `SECURITY DEFINER` function in the exposed schema executable by `service_role` ONLY -> the linter only flags exposed definer functions that `anon`/`authenticated` may execute, so the task's "SECURITY DEFINER + service_role only" is both compliant and lint-clean.
- [2026-10-22] [consume_reward / begin_ad_reward]: thin `SECURITY INVOKER` wrappers in `public` over a `SECURITY DEFINER` implementation in the non-exposed `private` schema -> a signed-in user must be able to consume its own reward and open its own ad view, but a public definer callable by `authenticated` would add a new `authenticated_security_definer_function_executable` finding (A1 documented this lint as open by design; A7 adds nothing to it).
- [2026-10-22] [Idempotency]: the ledger key is `(source, transaction_id)` with a partial unique index, and the SSV callback is additionally gated by a single-use `ad_view_tokens` row -> a replayed AdMob ping must never grant twice, and the token is what binds the reward to the user who actually watched the ad.
- [2026-10-22] [AdMob signature]: the Edge Function refuses to grant unless `ADMOBSIGNING_KEY` is configured and the RSA-SHA256 signature of the canonical query string verifies against it -> the MCP exposes no `secrets set` tool, so the function ships FAIL-CLOSED and the operator must set the secret; verifying with the key carried by the request would be security theatre (an attacker would sign with their own key).
- [2026-10-22] [Canonical query string]: the verifier accepts the three reasonable encodings of the canonical string (raw / percent-encoded / decoded) and rejects when NONE matches -> Google's spec is ambiguous about the encoding of the values; accepting a valid signature under any documented encoding keeps the integration working without ever accepting an unverified request.
- [2026-10-22] [Sponsor logos]: `sponsors.logo_path` points at the existing `group-covers` bucket -> a dedicated `sponsor-logos` bucket would add storage surface for public artwork that fits the existing bucket policy.
- [2026-10-22] [Streak mercy limit]: one mercy per 30 days is enforced in `grant_reward` (and pre-checked in `begin_ad_reward`) -> the product plan says "1x/month"; enforcing it at grant time (not only in the UI) keeps the rule true even if a second path ever grants.
- [2026-10-22] [Streak mercy limit — alternative rejected]: a calendar-month limit was rejected in favour of a rolling 30-day window -> the grace period is 30 days, so a rolling window is the honest reading of "repairs 1 missed day per month" and needs no month-boundary bookkeeping.
- [2026-10-22] [Client write privileges]: `INSERT/UPDATE/DELETE/TRUNCATE/TRIGGER/REFERENCES` are revoked from `anon` and `authenticated` on every A7 table -> the platform grants ALL on new tables by default, and RLS alone does not protect against `TRUNCATE`.
