# A1 — Schema Foundation decisions

Format: `[YYYY-MM-DD] [Topic]: Decision -> Reason (why alternatives failed)`

- [2026-10-21] [Extensions]: pgcrypto was already installed by the platform into `extensions`; A1 did NOT force-install a duplicate and did NOT rely on pgcrypto for uuid defaults -> PostgreSQL 17 ships `pg_catalog.gen_random_uuid()` natively, so every `uuid` default works with or without pgcrypto.
- [2026-10-21] [pg_cron schema]: pg_cron's extension entry lands in `pg_catalog` while its callables live in the extension-owned schema `cron` -> the extension script creates schema `cron` itself, so `WITH SCHEMA extensions` only moves the catalog entry; `cron.schedule(...)` must be called fully qualified.
- [2026-10-21] [pg_net schema]: pg_net's extension entry lands in `extensions` while its callables live in the extension-owned schema `net` -> same mechanism as pg_cron; `net.http_post(...)` must be called fully qualified.
- [2026-10-21] [Cron]: `cron.schedule(job_name, cron_expression, command)` is installed AND verified working on this project (scheduled, read back from `cron.job`, unscheduled) -> A8 can rely on it; no "pg_cron is not loaded" error was observed.
- [2026-10-21] [pg_net]: `net.http_post(url :=, body :=, headers :=)` is installed AND verified with a real HTTPS round trip (response body read back from `net._http_response`) -> A8 can rely on it for Edge Function calls.
- [2026-10-21] [practice_points uniqueness]: used `UNIQUE NULLS NOT DISTINCT (group_id, practice_kind)` instead of a plain UNIQUE plus a partial unique index -> PostgreSQL 15+ supports it natively (project is PG 17.11) and it expresses the "one global default per practice_kind" rule in a single constraint; a plain UNIQUE would allow unlimited global rows because NULLs are distinct.
- [2026-10-21] [pgTAP harness]: added `public.pgtap_summary()` returning one jsonb row with a PASS/FAIL verdict -> the MCP `execute_sql` tool returns only the LAST non-empty result set, and pgTAP's `finish()` returns ZERO rows on success, so the standard `select * from finish();` tail is not a reliable pass/fail signal (a file whose 3rd assertion failed but whose 81st passed would look green).
- [2026-10-21] [pgTAP harness]: `public.pgtap_summary()` calls `extensions._get('failed')` and NOT `extensions.num_failed()` -> `num_failed()` is a LANGUAGE sql function whose body calls `_get()` unqualified, which fails with `function _get(unknown) does not exist` when invoked from a function with `set search_path = ''` (migration `0009`).
- [2026-10-21] [RLS helpers]: kept the 5 membership helpers as `security definer` in `public` with the exact names mandated by CONVENTIONS §4 -> SECURITY DEFINER is required for recursion safety under RLS, and 9 agents depend on these names; renaming/moving them would break every downstream policy for a lint that is only a WARN.
- [2026-10-21] [RLS helpers]: revoked the default PUBLIC grant on the 5 SECURITY DEFINER helpers and re-granted only `authenticated` + `service_role` -> `REVOKE … FROM anon` alone was ineffective because the default ACL grants EXECUTE to PUBLIC and `anon` is a member of PUBLIC; `authenticated` MUST keep EXECUTE because PostgreSQL evaluates RLS policy expressions with the querying role's privileges (verified: revoking it produces `42501 permission denied for function is_group_member`).
- [2026-10-21] [profiles RLS]: no INSERT policy and no DELETE policy for clients on `public.profiles` -> A2's `handle_new_user` trigger (SECURITY DEFINER) is the only writer and A2 owns account deletion; a client-writable profile table would break the sacred-privacy invariant.
- [2026-10-21] [groups RLS]: no `anon` SELECT policy -> a fraternity is private and a challenge is public; A3 owns the logged-out "public group preview" policy and must add it (cross-domain request recorded in SCHEMA.md §10.1).
- [2026-10-21] [audit_log]: `actor_id` is deliberately NOT a foreign key to `public.profiles` -> the audit trail must survive the hard deletion of the actor during A2's account erasure.
- [2026-10-21] [practice_kind]: documented the "confession is private-only" rule in `comment on type public.practice_kind` -> PostgreSQL 17 has no `comment on enum value` syntax (verified), so a per-value comment is impossible.
- [2026-10-21] [Test harness]: every test file is wrapped in `begin; … rollback;` and the connection is pooled -> the `rollback;` is what guarantees a failing test leaves nothing behind; verified: 0 rows remain in auth.users / profiles / groups / group_members / user_blocks after the A1 suite.
