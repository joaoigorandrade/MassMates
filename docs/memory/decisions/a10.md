# A10 — decisions — security & QA audit

- [2026-10-22] [Helper signatures]: the five RLS helpers became SELF-SCOPED (`public.is_group_member(p_group_id uuid)`, `public.is_group_admin(p_group_id uuid)`, `public.is_blocked(p_other_id uuid)`, `public.is_group_member_of_any()`, `public.is_any_group_admin()`); the two-user logic moved to `private.is_*_impl` -> every policy in the project already passed the CALLER's own id as the second argument, so the two-argument form was never needed by a policy and only served as an enumeration oracle: a signed-in user could call `/rest/v1/rpc/is_group_member {"p_group_id":…,"p_user_id":…}` and learn whether an ARBITRARY user belonged to an ARBITRARY group, and `is_blocked` leaked the whole block graph.
- [2026-10-22] [Helper implementation]: the helper bodies live in the non-exposed `private` schema as `SECURITY DEFINER` (`private.is_group_member_impl(uuid,uuid)` …) and the public helpers are thin `SECURITY INVOKER` wrappers that supply `auth.uid()` themselves -> a function in a schema PostgREST does not expose is unreachable over HTTP and invisible to the Supabase linter, so the helpers cost zero findings while every policy keeps working (PostgreSQL evaluates a policy expression with the querying role's privileges, so `authenticated` keeps EXECUTE).
- [2026-10-22] [Policy rewrite]: the two-argument helper call was dropped from every policy (40 policies across `public` and `storage`) and re-pointed at the self-scoped helper -> a policy can no longer express "is somebody ELSE a member?", so the oracle is closed at the language level, not just at the API level. The rewrite is a pure textual collapse of the second argument; the semantics are unchanged.
- [2026-10-22] [Domain RPCs]: the 28 flagged domain RPCs (A4's 7, A5's 11, A6's 10) were moved to `private.<name>_impl` and their public counterparts became `SECURITY INVOKER` wrappers -> `get_advisors({type:"security"})` went from 33 `authenticated_security_definer_function_executable` findings to ZERO. The body was moved VERBATIM by reading it back with `pg_get_functiondef()`, so no 500-line body was ever re-typed.
- [2026-10-22] [Signature preservation]: the public wrappers keep the exact argument names, types, DEFAULTS, return type and error behaviour of the originals -> A9 is calling them by name; a renamed argument or a changed default would be a breaking change, and `CREATE OR REPLACE` re-points the dependency without dropping the object.
- [2026-10-22] [Grant hygiene]: every function is revoked from `PUBLIC` AND from `anon` explicitly, then granted to `authenticated` and `service_role` -> the project's default ACL grants `anon` EXECUTE on new `public` functions DIRECTLY; revoking "from public" alone leaves that grant in place and the function stays reachable as an unauthenticated RPC (A6 found this, A10 verified it on every function it touched).
- [2026-10-22] [A3 preview seam fixed]: `grant usage on schema a3_preview to authenticated, service_role` + the matching `grant execute` on the two preview implementations (migration 0903) -> the wrappers are `SECURITY INVOKER`, so a SIGNED-IN user got `42501 permission denied for schema a3_preview` from `public.preview_group_by_code` and `public.list_featured_challenges`. The logged-out discovery worked; the same list failed for every authenticated user. Pre-existing since A3's migration 0208.
- [2026-10-22] [join_group_by_code FOUND bug fixed]: `private.join_group_impl` now captures `FOUND` into `v_has_invite` immediately after the `SELECT … INTO v_invite` (migration 0904) -> the `INSERT INTO group_members` in between RESET `FOUND` to true, so the invite-usage branch always ran; with no `group_invites` row the UPDATE matched nothing, `v_uses` stayed NULL and the join failed with the misleading "this invite code has reached its usage limit". Reachable: a group admin can set `groups.invite_code` directly through the `groups_update_admin` policy, and then NOBODY can join with that code.
- [2026-10-22] [anon surface]: `anon` may now execute EXACTLY four public functions — `preview_group_by_code`, `list_featured_challenges`, `get_today_liturgy`, `get_liturgical_calendar` -> they are the documented logged-out entry points; `public.current_user_id()` was revoked from `anon` and `public.probe_wrapper()` (a leftover debug echo) was restricted to `service_role`.
- [2026-10-22] [unindexed_foreign_keys]: the two remaining findings were fixed by A8 itself in `0706_index_guardian_angel_foreign_keys` -> A10 measured the advisor BEFORE and AFTER its own work and did not duplicate the index (A8 applied it concurrently at 00:35).
- [2026-10-22] [unused_index baseline]: the 26 remaining `unused_index` findings are ACCEPTED and documented in SCHEMA.md §21 -> the tables are empty, so the planner cannot prove an index unused; every one of them backs a foreign key, a unique constraint or a documented lookup path, and dropping one would immediately re-open `unindexed_foreign_keys`.
- [2026-10-22] [RLS matrix]: `supabase/tests/a10/rls_matrix.sql` asserts the number of rows each of the FIVE personas (anon, outsider, member, admin, blocked) can reach with SELECT / UPDATE / DELETE on EVERY one of the 39 public tables -> 647 assertions; the expectations are hand-written, so a silent policy widening (or narrowing) fails the build. The probe helpers raise a deliberate exception so the probe runs in a sub-transaction and the fixture survives for the next persona.
- [2026-10-22] [RPC matrix]: `supabase/tests/a10/rpc_matrix.sql` asserts the whole privilege matrix (who may execute what), the exact SQLSTATE + message of the non-member error contract of 23 RPCs, and the JSON shape of 40+ happy paths -> 85 assertions. The shapes were cross-checked against SCHEMA.md; where the doc and the implementation disagreed the IMPLEMENTATION was wrong and was fixed (the `a3_preview` seam, the `join_group_by_code` bug).
- [2026-10-22] [Privacy audit]: `supabase/tests/a10/privacy.sql` proves the sacred-privacy invariants end to end -> 65 assertions: the catalog scan (no table/column/bucket can hold a confession or a diary entry), the enforced CHECK constraints, the end-to-end flow (Alice creates a fraternity, Bob joins with the 6-digit code, a group check-in with a reflection fans out, a private check-in WITH content is rejected, a private check-in WITHOUT content is stored with NULL content, a confession cannot be shared), the fan-out counts, the streak/ring maths, the outbox and audit-log silence, the Guardian Angel anonymity, and the moderation path.
- [2026-10-22] [Edge Function audit]: all four deployed functions were smoke-tested with malformed and unsigned requests -> every one answers 4xx JSON, never a 500, and grants nothing. `admob-ssv` fails closed with `signing_key_not_configured` (the `ADMOBSIGNING_KEY` secret is NOT set), `push-dispatch` fails closed with 401 (the shared secret is NOT set), and the two `verify_jwt: true` functions reject a missing and an invalid token.
- [2026-10-22] [No hard-coded secrets]: every secret is read from `Deno.env` -> the deploy tool has no secret store, so the operator sets them with `supabase secrets set`; the required list and its current state are in `docs/backend/API.md`.
