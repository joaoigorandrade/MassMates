## 2. iOS custom scheme + redirect URLs

### 2.1 Register the URL scheme (A9 — `Project.swift`)

The app owns the `massmates://` scheme. Add it to the app target's
`infoPlist` (currently `Project.swift` → `MassMates` target → `infoPlist:
.extendingDefault(with: [...])`):

```swift

    with: [
        "UILaunchScreen": [
            "UIColorName": "",
            "UIImageName": "",
        ],
        "CFBundleURLTypes": [
            [
                "CFBundleURLName": "joaoigor.MassMates",
                "CFBundleURLSchemes": ["massmates"],
            ]
        ],
    ]
),
```

Afterwards run `make rebuild` (the `infoPlist` is baked into the bundle).

### 2.2 Redirect URLs to allow (dashboard → Authentication → URL Configuration → Redirect URLs)

```
massmates://auth/callback
massmates://join/:code
```

plus the **native iOS** form used by the OAuth providers:

```
massmates://auth/callback?provider=apple
massmates://auth/callback?provider=google
```

`massmates://join/:code` is the **invite deep link** (A3): the `:code` is the
6-digit `public.groups.invite_code`. It is *not* an auth redirect — it is
allowed here only because the dashboard accepts a single list; GoTrue will
never redirect to it during an auth flow.

### 2.3 The provider callback (server side)

Apple and Google redirect the **browser** to:

```
https://khovpljkitslmjmonuzu.supabase.co/auth/v1/callback
```

This URL is generated by the dashboard automatically — do not add it to the
iOS allow-list, and do not add it manually to the provider consoles either
(it is what the dashboard shows you in the Apple/Google provider card).

## 3. Sign in with Apple

### 3.1 Apple Developer account (once)

1. <https://developer.apple.com/account/resources/identifiers/list> →
   **Identifiers** → **+** → **Service IDs** → **Web Services IDs**.
2. Description `MassMates`, Identifier `joaoigor.MassMates` (the reverse-DNS
   form of the bundle id `joaoigor.MassMates`).
3. Enable **Sign in with Apple** → configure the **Return URL**:
   ```
   https://khovpljkitslmjmonuzu.supabase.co/auth/v1/callback
   ```
4. Create a key: **Keys** → **+** → **Continue** → **Sign in with Apple** →
   register `joaoigor.MassMates` → download the **`AuthKey_<TEAMID>.p8`**
   (it is downloadable **once**).
5. Note down: **Team ID**, **Key ID**, and the `.p8` content.

### 3.2 Supabase dashboard → Authentication → Providers → Apple

| Field | Value |
|---|---|
| Enable Apple provider | **on** |
| Client ID | the Apple **Service ID** (`joaoigor.MassMates`) |
| Client Secret | the **`.p8` private key** (paste the whole PEM) |
| Nonce | leave **empty** — the app generates and sends its own nonce (§3.4) |

Save. The dashboard shows the callback URL again — it must match the Return URL
configured in the Apple Developer portal **exactly**.

### 3.3 iOS side

`SignInWithAppleButton` (SwiftUI) → `ASAuthorizationController` →
`ASAuthorizationAppleIDCredential`:

* the app generates a **random nonce** (`randomNonceString()`, ≥ 16 chars from
  the allowed alphabet);
* **Apple** receives `SHA256(nonce)` (`request.nonce = sha256(nonce)`);
* **GoTrue** receives the **raw nonce** (see §8.3) — GoTrue hashes it and
  compares it with the `nonce` claim that Apple put in the identity token.

Request only `requestedScopes = [.fullName, .email]`.

The **full name** comes only on the *first* authorization for that Apple ID —
send it to the profile RPC right after the first sign-in (see §9).

### 3.4 Verify

```bash
curl -s -X POST "https://khovpljkitslmjmonuzu.supabase.co/auth/v1/token?grant_type=id_token" \
  -H "apikey: <publishable key>" -H "Content-Type: application/json" \
  -d '{"provider":"apple","id_token":"<apple identity token>","nonce":"<raw nonce>"}'
```

A success returns `{"access_token":…,"refresh_token":…,"expires_in":3600,…}`.

## 5. Email — magic link / OTP

### 5.1 Dashboard → Authentication → Email

* **Enable Email provider** → **on**.
* **Confirm email** → **on** in production (the app shows a "check your inbox"
  step). Turn it **off** only for local smoke tests.
* **Email magic link** → **on** (the template decides whether the message
  contains a *link* or a *6-digit code*).
* **Email OTP** → the same screen exposes the one-time-code template; the
  verification call is identical (§8.2).

### 5.2 SMTP is mandatory for production

Supabase's built-in SMTP relay (`supabase-mailer`) is rate-limited to a
couple of messages per hour **per project** and is **not for production** —
it will black-hole the magic links of real users and the SMTP quota error is
what the app sees as "we could not send your code".

Configure a real provider (**Authentication → SMTP**):

| Field | Example (Resend) | Notes |
|---|---|---|
| SMTP host | `smtp.resend.com` | |
| SMTP port | `465` (TLS) / `587` (STARTTLS) | |
| Username | `resend` | |
| Password | the provider API key | stored in the dashboard, never in git |
| Sender | `MassMates <login@yourdomain.com>` | must be a verified domain |

Send the test email from the dashboard before shipping.

### 5.3 iOS side

1. The app posts `{email}` to `/auth/v1/otp` (§8.1) → the user gets a code.
2. The app posts `{email, token, type}` to `/auth/v1/verify` (§8.2) → it gets
   the session (access + refresh token).

## 6. Post-sign-up: what the backend already does

| Step | Where |
|---|---|
| A profile row is created **automatically** | `public.handle_new_user` trigger on `auth.users` (A2, migration `0101`) — display name from `full_name`/`name`/`user_name`/email local part, locale `pt-BR`, timezone `America/Sao_Paulo`, ad consent **always false**. |
| The profile is read | `public.get_my_profile()` → jsonb (A9: call it right after the session is created). |
| The profile is edited | `public.update_my_profile(...)` — only the non-NULL arguments are applied. |
| Ad consent | `public.update_ad_consent(p_analytics, p_personalization)` — the only GDPR consent surface; every call is written to `public.audit_log`. |
| The account is deleted | `public.request_account_deletion()` → `public.confirm_account_deletion(token)` → Edge Function `delete-account` (two taps). |

> The app must **not** write `public.profiles` directly: the columns are
> validated server-side (locale, timezone, `avatar_path` must start with
> `avatars/`, `rule_of_life` must be an array of `{kind,label}` with a valid
> `public.practice_kind`).

## 7. Session lifecycle

| Action | Call |
|---|---|
| Refresh | `POST {url}/auth/v1/token?grant_type=refresh_token` — body `{refresh_token}` |
| Current user | `GET {url}/auth/v1/user` — header `Authorization: Bearer <access_token>` |
| Update profile in auth | `PUT {url}/auth/v1/user` — body `{data: {full_name, avatar_url, locale, timezone}}` |
| Sign out (this device) | `POST {url}/auth/v1/logout` — body `{}` |
| Sign out (all devices) | `POST {url}/auth/v1/logout` — body `{"scope":"global"}` |

The access token is a JWT: `sub` (the user id = `public.profiles.id`),
`email`, `role`, `aal` (assurance level: `aal1` = email/password, `aal2` =
refreshed OAuth), `amr`, `session_id`, `exp`, `iat`.

The app stores the session (Keychain) and refreshes it **proactively** ~60 s
before `exp`.

## 8. Exact GoTrue endpoints and payloads for A9

> Base URL `U = https://khovpljkitslmjmonuzu.supabase.co`.
> Every request: `apikey: <publishable key>` + `Content-Type: application/json`.
> A9 implements these with `Networking` (`APIRequest` / `HTTPRequest`).

### 8.1 Request the email OTP / magic link

```http
POST U/auth/v1/otp
Content-Type: application/json
apikey: <publishable key>

{
  "email": "user@example.com",
  "create_user": true,
  "email_redirect_to": "massmates://auth/callback",
  "data": { "full_name": "Maria Silva" }     // optional -> raw_user_meta_data
}
```

* `create_user: true` → signs up on the first request, logs in afterwards.
* `data` lands in `raw_user_meta_data` → the `handle_new_user` trigger uses
  `full_name` for `display_name` and `avatar_url` for `avatar_path`.

### 8.2 Verify the code / magic-link token

```http
POST U/auth/v1/verify
Content-Type: application/json
apikey: <publishable key>

{
  "email": "user@example.com",
  "token": "123456",              // the 6-digit code, or the token from the link
  "type": "email"                 // "email" | "magiclink" | "sms"
}
```

Response (same shape as §8.3):

```json
{ "access_token": "...", "refresh_token": "...", "expires_in": 3600,
  "token_type": "bearer", "user": { "id": "<uuid>", "email": "…", "…": "…" } }
```

### 8.3 Exchange an Apple / Google identity token

```http
POST U/auth/v1/token?grant_type=id_token
Content-Type: application/json
apikey: <publishable key>

{
  "provider": "apple",            // or "google"
  "id_token": "<identity token>",
  "nonce": "<raw nonce>"          // REQUIRED for apple; optional for google
}
```

* The `nonce` is the **raw** nonce the app generated; GoTrue hashes it
  (`SHA256`) and compares it with the `nonce` claim Apple put in the identity
  token. Apple must have received the **hashed** value (`request.nonce`).
* `provider: "apple"` also accepts `id_token` + `nonce` + `access_token` /
  `refresh_token` (the "sign in, then link" flow).
* If the identity token already carries a `nonce` claim, the `nonce` field is
  **mandatory**, otherwise GoTrue answers
  `{"error_code":"invalid_nonce"}`.

### 8.4 Refresh the session

```http
POST U/auth/v1/token?grant_type=refresh_token
Content-Type: application/json
apikey: <publishable key>

{ "refresh_token": "..." }
```

### 8.5 Read the current user

```http
GET U/auth/v1/user
apikey: <publishable key>
Authorization: Bearer <access_token>
```

### 8.6 Sign out

```http
POST U/auth/v1/logout
apikey: <publishable key>
Authorization: Bearer <access_token>

{ "scope": "global" }     // omit for "this device only"
```

### 8.7 The RPC surface A9 needs (PostgREST, not GoTrue)

Base: `POST {url}/rest/v1/rpc/<name>` with `apikey` + `Authorization` +
`Content-Type: application/json`.

| RPC | Body | Returns |
|---|---|---|
| `get_my_profile` | `{}` | the profile row as jsonb |
| `update_my_profile` | `{"p_display_name":"…","p_avatar_path":"avatars/<uid>/x.png","p_parish":"…","p_city":"…","p_timezone":"America/Sao_Paulo","p_locale":"pt-BR","p_ad_consent_analytics":false,"p_ad_personalization":false,"p_rule_of_life":[{"kind":"rosary","label":"Rosário da manhã"}]}` | the updated row as jsonb |
| `update_ad_consent` | `{"p_analytics":false,"p_personalization":false}` | `{id, ad_consent_analytics, ad_personalization, updated_at}` |
| `request_account_deletion` | `{}` | `{id, confirmation_token, requested_at, expires_at, status, created}` |
| `confirm_account_deletion` | `{"p_token":"<uuid>"}` | `{id, confirmation_token, requested_at, confirmed_at, expires_at, status}` |

**Error contract:** every validation failure comes back as
`{"code":"22023","message":"<error_key>","hint":"…"}` with one of the keys
`invalid_display_name · invalid_avatar_path · invalid_locale ·
invalid_timezone · invalid_parish · invalid_city · invalid_rule_of_life ·
invalid_rule_of_life_kind · invalid_rule_of_life_label · rule_of_life_too_long ·
invalid_ad_consent · invalid_deletion_token · deletion_token_expired`.
`not_authenticated` (42501) and `profile_not_found` (P0002) are the two
non-validation errors. A9 maps the keys to the pt-BR / en strings.

**Account deletion (two taps):** tap 1 `request_account_deletion` (keep the
`confirmation_token` — it expires 15 minutes after the request), tap 2
`confirm_account_deletion` → then call the Edge Function:

```http
POST {url}/functions/v1/delete-account
Authorization: Bearer <access_token>
Content-Type: application/json

{}
```

`200 {"ok":true,"deleted":true}` on success; `409 {"ok":false,
"error":"deletion_not_confirmed"}` when the request was not confirmed.

## 10. Known limitations / follow-ups

* The **default Supabase SMTP** (≤ 2 emails/hour/project) must be replaced
  before the first real user (§5.2).
* **OAuth providers are not configured yet** — the dashboard steps in §3 and
  §4 have to be executed by a human; until then only the email flow works.
* The **Apple `.p8` key can only be downloaded once** — store it in the
  password manager of the team, not in the repository.
* `massmates://auth/callback` must be registered **both** in the dashboard
  (Redirect URLs) and in `Project.swift` (`CFBundleURLTypes`), otherwise the
  magic link lands in a browser that cannot hand the session back to the app.
* The app never needs the **service-role key**; `delete-account` is the only
  component that uses it, and it lives in the Edge Function.
